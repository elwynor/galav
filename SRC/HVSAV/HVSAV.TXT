1. WHAT IS AUTO VALIDATOR?
--------------------------

Auto Validator checks that a new user has a working email address, then
upgrades their account automatically.

  1. A new user enters Auto Validator and types their email address.
  2. Auto Validator emails them a four-character validation code.
  3. The user calls back, enters Auto Validator again, and types the code.
  4. Auto Validator validates them: it can switch them to a new class,
     give them a key, and post credits - whatever you set up for the
     validation method.

Version 2.1.0 validates by email only.  The phone call-back and postal
mail methods of version 2.0 have been retired.


2. INSTALLING
-------------

  1. Copy HVSAV.DLL, HVSAV.MDF, HVSAV.MSG and HVSAV.TXT into your BBS
     directory.
  2. Run the Menu Tree editor and add Auto Validator to your menu.
  3. Make sure your Internet mail (SMTP) gateway is set up and can send
     mail out - Auto Validator sends codes through it.
  4. Start the BBS.

On first start Auto Validator creates its data files:

  HVSAVUSR.DAT   one record per user who has used Auto Validator
  HVSAVSET.DAT   Auto Validator's settings

UPGRADING FROM 2.0: keep your existing HVSAVUSR.DAT - 2.1.0 reads it as
is, including codes that were already sent.  HVSAVCFG.DAT and
HVSAVNVR.DAT (phone settings and the "never call" list) are no longer
used and can be deleted.  The activation code is gone; no registration
is needed.


3. SETTING IT UP
----------------

Settings are changed ONLINE, from the Auto Validator sysop menu, and take
effect immediately - no restart.  The options in the configuration editor
(HVSAV.MSG, levels 3 and 4) are only the install defaults: they are copied
into HVSAVSET.DAT the first time the module starts.  To copy them in
again later, use "Reset all settings" in the sysop menu.

Enter Auto Validator with the sysop key (SYSOP by default) to get the
sysop menu:

  S  Settings        - change any setting below
  L  Look up a user  - see a user's validation record
  G  Global commands - list the sysop commands (section 5)
  X  Exit

Each settings change is written to the Audit Trail and the activity log.

GENERAL SETTINGS

  Key needed to request validation   Only users with this key may use
                                     Auto Validator.  Blank = anyone.
  Key for sysop menu and commands    Users with this key get the sysop
                                     menu and commands, and are never
                                     validated themselves.  Blank = SYSOP.
  Method used for email validations  Which method (1-5) a user gets when
                                     they enter a correct code.
  Max validated users per email      How many validated users may share
                                     one email address.
  Failed validations allowed         Three wrong codes in one visit count
                                     as one failure.  After this many
                                     failures the user must be reset by a
                                     sysop.  0 = no limit.
  Offer validation at logon          YES: unvalidated users are asked at
                                     logon whether to validate now.
  Global command trigger             First character of the sysop
                                     commands (default @).
  Email type shown to users          How email is described to users,
                                     e.g. "Internet".
  Internet email address prefix      Put in front of the user's address
                                     to route the message out through
                                     your Internet mail gateway
                                     (default IN:).
  Email domain refused               A domain users may not validate
                                     with - usually your own BBS's.
  Activity log file                  Text log of every validation,
                                     failure and sysop action.  Blank =
                                     no log.  Default HVSAV.LOG.

VALIDATION METHODS 1-5

Each method has four settings:

  Class to switch to    The class the user is switched to.  It must exist
                        in your Accounts setup - Auto Validator will not
                        let you choose a class that does not exist, and
                        skips the switch (with an Audit Trail warning) if
                        the class is later removed.  Blank = no change.
  Key to give           A key added to the user.  Blank = none.
  Credits to post       Credits added to the account.  0 = none.
  Credit type           FREE or PAID, for your accounting.

REFUSING ADDRESSES

Besides the refused domain setting, you can create HVSAVBAD.TXT in the
BBS directory with one entry per line.  Any address that contains one of
the entries (upper or lower case) is refused.  For example:

     MAILINATOR.COM
     @MYBBS.EXAMPLE


4. WHAT USERS SEE
-----------------

A new user entering Auto Validator is asked whether to begin email
validation, then for their email address.  The address must look like
name@example.com.  The code is emailed, and the user is told to come
back.

When they return, Auto Validator asks for the code.  They have three
tries per visit.  A correct code validates them at once.

Users who are already validated, who lack the request key, or who have
used up their failed attempts are told so and returned to the menu.

The wording of every screen is in HVSAV.MSG (level 6) and can be changed
in the configuration editor.  Values such as the user's address appear
as text variables (HVS_EMAIL, HVS_CODE, ...) that you may move or remove.
The email itself is the YOUVAL message; its subject is EMLSUBJ.


5. SYSOP GLOBAL COMMANDS
------------------------

Usable from anywhere on the system by users with the sysop key.  Shown
here with the default trigger, @.

  @V n user   Validate a user with method n (1-5).
              Example: @V 1 Some User
  @D user     Devalidate: clears validated status, attempts and any
              pending code, so the user can validate again.  (Their
              class is not changed back.)
  @E user     Email the user their code again (a new code is made if
              they have none).
  @L user     Show the user's validation record.
  @O user     Toggle the override: an overridden user is not stopped by
              the failed-attempt or shared-address limits.
  @?          List these commands.


6. FILES
--------

  HVSAV.DLL      the module
  HVSAV.MDF      module description
  HVSAV.MSG      text and install-default options (the BBS builds
                 HVSAV.MCV from it)
  HVSAV.TXT      this manual
  HVSAVUSR.DAT   user validation records (created automatically)
  HVSAVSET.DAT   settings (created automatically)
  HVSAV.LOG      activity log (name set in the settings)
  HVSAVBAD.TXT   optional list of refused addresses (you create it)
